# AI Workflow Editor Spec 0511

## Context

AI Workflow V1 is active on `feat/ai-workflow-v1`. The backend can store workflow templates, validate graph JSON, run workflow executions, pause for human gates, and resume arena winner flows. The web editor uses React Flow for the canvas.

The previous implementation gap was not the React Flow choice. The gap was that the editor did not meet the expected n8n/Dify-style workflow authoring loop: users could only click node-library buttons to add nodes, and node positions were not persisted. Commit `95407fc9` fixed palette-to-canvas drag/drop and layout persistence.

## Product Goal

Make the workflow editor feel like a real node workflow builder:

- Build workflows visually from a node palette.
- Drag nodes onto a canvas at the intended position.
- Move nodes and save their layout.
- Connect nodes without creating backend-invalid graphs.
- Configure node behavior from an inspector.
- Validate the graph before saving or running.
- Start a test run from the editor once the graph is valid.

React Flow remains the right foundation for the editor because it already provides canvas panning, zooming, node movement, handles, selection, minimap, and coordinate conversion.

## Current State

Completed:

- Workflow template list, create, copy, update, and delete APIs exist.
- Workflow graph model exists in the frontend.
- Built-in workflow templates exist in the backend.
- Editor renders React Flow nodes and edges.
- Canvas supports node movement, edge connection, pan, zoom, controls, and minimap.
- Node inspector edits node data.
- Basic validation panel exists.
- Node palette supports drag/drop into the canvas.
- Node positions persist through graph save/load.
- Workflow run pages show run dashboard, run canvas, human gate controls, retry, cancel, and arena winner selection.

Known gaps:

- Frontend validation is weaker than backend validation: cycles and unreachable nodes can still pass the editor panel until save/run hits backend validation.
- Edge authoring is still primitive. There is no edge inspector, edge label editing, or explicit branch mapping UI.
- Condition branches are configured separately from drawn edges, so users can create confusing graphs.
- The editor has no direct "Run test" action yet.
- Canvas editing lacks common productivity actions such as duplicate, delete selected, auto layout, undo/redo, and keyboard shortcuts.
- Drag/drop has type and CI coverage, but still needs browser smoke coverage when a full dev server is available.

## Stage 0511 Scope

Stage 0511 focuses on making the editor safer and closer to the expected visual workflow product without changing the backend schema.

In scope:

1. Bring frontend validation closer to backend validation.
2. Keep the node palette drag/drop behavior.
3. Preserve positions and avoid layout loss.
4. Make validation messages actionable enough that invalid graphs are blocked before save.
5. Prepare the next UI step for edge/branch authoring.

Out of scope for this stage:

- Replacing React Flow.
- Rewriting workflow runtime.
- Introducing a new workflow graph schema version.
- Building a full n8n clone.
- Reworking unrelated kanban, arena, workspace, or chat UI.

## Validation Requirements

The editor must flag these graph errors before save:

- Unsupported graph version.
- Missing or multiple Start nodes.
- Missing End node.
- Duplicate node IDs.
- Edge source or target missing.
- Self-edge.
- Cycle in the graph.
- Unreachable node from Start.

The validation panel remains always visible. The Save button stays disabled when errors exist.

## Next Stage After 0511

Recommended next stage:

- Edge authoring and branch mapping:
  - Show edge labels by type.
  - Add edge selection and inspector.
  - Let human gate outputs map to approval/rejection paths.
  - Let condition branches map directly to target nodes.
  - Let arena nodes mark the winner edge clearly.

This is the next biggest usability gap after drag/drop and validation parity.
